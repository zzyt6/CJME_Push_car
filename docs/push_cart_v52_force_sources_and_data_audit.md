# V5.2 本体估力：外部方案与采集核查

本轮以全身本体/控制历史估力、两引擎验证为主，额外核查数据采集。结论依靠原始论文、固定提交的官方代码和本项目实际仿真记录；不会把论文方法名称当作精度保证。

## 本项目采集链条

每个控制步先用旧观测产生动作，执行四个 5 ms 物理子步，再构造新观测；标签是刚完成 20 ms 内的双手反力均值。采集保存同一次返回的新观测与对应 `interaction_target`，不把下一步动作或未来力放入当前输入。

两端都表达“手对车”的力：力矩参考点是各手掌原点，坐标轴为控制步末的车航向坐标系。Isaac 先平均世界系子步 wrench 再旋转；MuJoCo 使用相同末时刻 yaw 旋转各子步再平均，两者在线性旋转下等价。两端都在评分时用相同固定抓握几何合成为把手中心 `[Fx,Fy,Mz]`。

仍需保留的区别：Isaac 标签是手子树 Newton–Euler 重建；MuJoCo 标签由 weld 约束重建。它们并非来自独立的同一力传感器。各子步力矩参考点轻微运动的处理、约束柔顺性、接触和数值加速度也可能影响动态标签。不能因为同名、同维度就认为已标定一致。

## 已执行的数据检查

- 主数据集 246,208 条，64 个环境；所有存储的输入/标签有限。
- 最早保留的 episode age 为 50，重置样本被剔除；环境、回合、age 组合无重复。
- 245,888 对同回合相邻样本的四帧重叠，在旧输入和新本体历史中均逐项相同，最大差为 0。
- 训练/验证/测试按完整环境划分，该环境全部回合保持在同一划分中。
- 重新采集后的旧观测、力标签、环境/回合编号和 age，与旧全输入训练数据完全相同；A.3 对照新增真实下肢动作历史。
- 435 维全身版本的上身目标取自已记录的实际目标，MuJoCo 中已与提交的 PD 目标逐帧核对；不需要从未知信息猜测上身动作。
- 新采集器额外记录实际车总质量、原始命令、平滑参考、有效物理子步数和 27 关节 PD 目标。原主数据没有逐样本实际载荷，不能追溯声称某载荷直方图已经验证；平滑任务参考已在原观测中。

机器可读核查见 `logs/bench/v52_falcon_explicit/falcon_a3/dataset_audit.json`；短采集验证保存在同目录 `collection_audit/`。

短采集实际完成 8 环境 × 256 控制步、1656 条有效样本：全部标签来自四个有效子步，记录的上身目标与实际提交 PD 目标的最大差为 0，八个场景的实际车总质量为 16.18–31.75 kg。该短实验用于核验新增记录字段，不作为全范围覆盖证明。

进一步用主训练环境确定各输入坐标的 1%–99% 分位区间，再检查留出和独立评测数据。最新帧 IMU 角速度超出区间的标量比例：Isaac 留出 1.88%、Isaac 评测 2.54%、MuJoCo 评测 17.74%；关节速度分别为 2.43%、2.02%、8.87%；上身目标分别为 2.02%、1.06%、6.27%。因此，输入分布变化不只是推测，已有记录支持。这里的比例以“样本数×字段维数”为分母，不是独立轨迹失败率；训练集自身约有 2% 超出其分位区间，也不能用单坐标区间证明完整多维覆盖。

完整分布检查和复现方式见 [输入覆盖报告](../logs/bench/v52_falcon_explicit/falcon_a3/feature_coverage.md) 与 `scripts/audit_v52_transfer_coverage.py`。评测命令网格与自然训练命令不同，所以报告同时保留独立 Isaac 评测作为参照。未用这些结果调模型、归一化或物理参数。

## 独立已知载荷检查与解释范围

使用项目已有的运动手臂已知载荷脚本，增加 V5.2 与显式 PD 入口。在两个初始航向的机器人上，施加正负静载、动态载荷与卸载，逐物理子步比较重建值与已知施加的反作用 wrench，并保留未校正的时延和瞬态误差。该检查没有推车或闭链抓握，不能替代闭链动态标签的独立标定。

首次诊断 `known_load_v52/` 保留为无效执行记录：诊断类未装载任务配置，只记录了 50 Hz 最末子步，而报告期望 200 Hz。未修改误差阈值；修正诊断类使其加载 V5.2 任务配置并逐子步记录，另存到 `known_load_v52_substeps/`。这处问题属于诊断脚本，不是已训练数据的历史拼接错误。

修正后的六个阶段均完成 400 个物理采样时刻，每次包含两个机器人、两只手；没有重置、无效或非有限样本。跨阶段、机器人、手的最大力向量 RMS 为 0.002719 N，最大力矩向量 RMS 为 0.000541 N·m；动态加载各手的力和力矩时延均为 0。载荷注入接口误差最大 4.30e-6 N / 9.34e-7 N·m。
这些数字验证的是开链、已知小载荷的符号、参考点和基础公式，不能推广为大载荷推车闭链标签已经校准。

进程记录补充：原短采集和修正探针均写出完整结果，但外层 shell 返回了 1，日志未给出异常原因，不能当作干净退出。为排除执行状态疑问，又在 `collection_audit_recheck/` 和 `known_load_v52_substeps_recheck/` 独立重跑，直接由 Python 子进程记录退出码，两者均为 0；记录见 `sampling_process_recheck.json`。首次 `known_load_v52/` 的无效诊断仍保留。

## 下一步应借鉴的采集设计

先对已知外力、未知接触反力分开做标定，再扩展姿态、速度、上下肢控制目标、外力方向/大小/频率和受力点。同步保存真实执行参数与标签来源，对零载、稳态、启停和转向分别评分。当前一次标称采样与五帧历史足以做受控对照，但不足以证明覆盖了跨引擎动态范围。

更长历史、共享状态编码器或运动学辅助监督都可作为后续网络对照；应保持同一数据和评测协议测试，不能从他人方案名称直接推断必然优于本项目。
