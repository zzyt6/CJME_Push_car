# V5.3 显式力／车速预测：现有成绩、sim2sim 补测与对照要求

日期：2026-09-28。回到高层推车策略，暂不扩展 HOMIE 的双手抗扰能力。本次没有重训或改变随机化范围；新增固定检查点 MuJoCo 评测和结果汇总。

**判断：当前没有证据证明现有输入噪声幅度是真机部署必需的范围；也没有证据证明 V5.3 已经优于 FALCON 或 Learning Force Control。** 当前 V5.3 在名义 Isaac 内的估计较准，但完整随机化下精度明显下降，迁移到当前 MuJoCo 部署场景后力、前向车速和角速度估计均存在明显差距。最终需要证明它改善闭环控制，而不仅是估计 loss 或运行不跌倒。

**这些成绩的边界**

- MuJoCo 使用当前入口的 `nominal + urdf + explicit_pd`，没有采用之前为物理对齐探索的 `rigid_limit + physx` 选项。
- Isaac 的手子树标签和 MuJoCo 的 weld 重建都按四个物理子步平均，但统一量纲、方向、采样周期不代表两端闭链动力学和标签已经完全等价。因此这里衡量的是当前实际 sim2sim 部署链路的整体差距，不是单独估计器结构的因果差距。
- 旧 V5.2 在 `rigid_limit + physx` 场景中得到过约 2.1–2.5 N 的逐手分轴 MAE，那是不同网络、不同场景、不同工况，不能拿来代替当前 V5.3 sim2sim 成绩。
- Isaac 名义与 L13 同时改变物理参数、传感器噪声、延迟与外部扰动，误差上升不能全部算在输入噪声头上。
- 本轮没有真实机器人测力／车速基准，没有新增独立训练种子，也没有重训降低噪声的估计器。

**与两个主要参考方法，当前究竟能比较什么**

| 对照 | 原工作能支持的结论 | 目前与我们对比的缺口 |
|---|---|---|
| FALCON 主方法 | 五帧本体历史、上下身双策略隐式外力适应；真机搬载、拉车、开门 | 主方法没有我们这样的显式双手 12 维估力输出；其机体／上身跟踪指标不是车速逐轴 MAE |
| FALCON A.3 显式估力对照 | 已知施加末端外力的预测曲线，估计力供下身策略及上身补偿使用 | 没有与本项目同工况、同口径的真机双手 wrench 和车速误差表；不能将主方法真机表现转给该对照 |
| Learning Force Control，ICRA 2024 | B1+Z1 并行学习力、身体速度等状态与策略；有测力计真机验证 | 论文真机 0–70 N、五个位置的约 5–10 N 是力跟踪误差；明确讨论估力偏高。估计机器人身体速度也不同于我们的车速 |

FALCON 论文表 1 的无／中／大外力下，主方法的 root tracking 指标为约 0.27/0.30/0.45，上身为 0.21/0.24/0.37。它们属于该文针对 252 个 ACCAD 动作目标的评测口径，不能与我们某一个 m/s 或 N 列直接排序。引用这张表时应保留其任务和指标定义。

Learning Force Control 在仿真里报告 Z 轴力跟踪低力目标约 5 N、整个范围低于 10 N，并说估力误差通常与跟踪误差相当或更大；真机估计力有过冲。它说明有用控制可以容忍估力误差，但不能证明本项目任何 5–10 N 的误差都可接受，也不能证明输入噪声越大越好。

论文：[FALCON](https://arxiv.org/html/2505.06776v2#S4)、[FALCON A.3](https://arxiv.org/html/2505.06776v2#A1.SS3)、[Learning Force Control 结果](https://arxiv.org/html/2405.01402v2#S5.SS1)。

**关于是否需要这么大的噪声，当前能下的结论**

1. 不存在“真机部署必须使用关节速度 ±2 rad/s、陀螺仪 ±0.5 rad/s、力矩上限 ±5% 偏置／白噪声”的已验证要求。这些是当前增强假设，不能用 HOMIE 的驱动扰动比例替代力矩读数标定。
2. 当前所谓“力相关噪声”主要施加在关节驱动力矩读数及本体观测，不是直接给真实末端力标签加同样误差。估计器训练标签保持对应仿真受力的周期均值。
3. 为了高精度，应以真实传感器误差及预期小幅模型残差确定主要训练分布；合理的物理随机化仍应覆盖真实质量、接触、增益和延迟。不应为追求名义仿真 MAE 把物理变化全部关掉。
4. 当前名义 MuJoCo 已关闭输入噪声，预测仍明显退化，说明当前训练增强没有消除部署链路差距；它不能单独判定“训练噪声太大”，也不能成为继续增大噪声的理由。
5. 可以把较大的噪声保留为压力测试；作为主要训练范围是否必要，应由重新训练后的精度—闭环性能对比决定。零噪声只能作为参考组，不是已经证明的真机方案。

**需要形成的实际对照，而不是跨论文拼分数**

在冻结 HOMIE 的现有任务内，对照应明确称为方法适配：FALCON 式本体历史估计输入、Learning Force Control 式历史状态联合估计，以及我们的力矩／DLS＋车速＋双手载荷方案。原论文分别是上下身联合策略和四足机械臂，完整系统复现不等于替换一个估计头。

- 固定机器人、车、驱动、抓握、任务、采样相位、训练数据与训练预算；把对照的共同目标限定为可对齐的逐手三维力和任务车速，额外六维力矩能力单独报告。Learning Force Control 的原始身体速度任务改为车速时，明确是本任务适配。
- 保留两组结果：同轨迹的估计器比较，以及为各输入方案重新训练高层 Actor 后的闭环比较。只替换力头且冻结 Actor 的成绩只能作为接口敏感性实验。
- 增加移除显式力／车速通道的等容量训练基线；预测替换为真值的仿真诊断用于估计可改善上限。测试时置零不是等价于从头训练的无估计器基线。
- 对当前模型的观测噪声做 0、0.25、0.5、1 倍候选组，物理分布保持一致。这些倍数仅是待试消融格点，不是建议立即设定的新默认；力矩偏置、白噪声、延迟应进一步分项，避免将多因素一起缩小后宣称找到了单一原因。
- 每组至少覆盖多个训练种子；开发与最终留出轨迹、工况和随机种子分开，不能用最终 MuJoCo 测试集反复调范围后仍称其独立验证。
- 估计端报告分轴 MAE、RMSE、bias、P95 和相位／响应延迟；控制端报告实际车速／路径误差、停止残余运动、失败／过载率、峰值与内部载荷。共同验收标准预先确定，优先选择满足控制与部署精度要求的配置。

只有完成这种同任务对照，才能回答“显式估计为什么值得用”以及“较小噪声是否既提高精度又保留迁移能力”。本轮补测确认了当前性能和缺口，没有将未完成的对照写成已经证明的优势。
