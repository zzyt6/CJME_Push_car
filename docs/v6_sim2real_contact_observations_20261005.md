# V6 实机部署：Dex3 接触方案与观测来源核查

核查日期：2026-10-05。范围：当前 V6 源码、仓库内 HOMIE 部署副本及已有接触文献记录。本次仅形成设计建议，不改变 V6 资产、网络、训练和部署代码；没有执行实机或新接触仿真实验。

## 1. 判断与建议

两个问题相互关联：永久固定连接既简化了抓握力学，也使机器人运动对小车运动具有很强的约束。允许真实手指变形、手掌沿杆滑移或绕杆旋转之后，原来的车速和双手载荷估计关系也需要重新验证。

建议保留 HOMIE 行走层作为起点，建立 **Dex3 独立限力闭合 + 真实可滑移接触 + 双臂协调/柔顺 + 接触状态监测** 的新实验版本。高层暂时继续控制速度指令和上身目标，不必立即学习全部手指动作。旧 V6 用作固定连接基线。

固定手指的闭合目标在实机上可以实现；实际手指仍由有限执行器力矩与接触决定位置。把手和手掌之间的六维相对位姿永久固定，则是另一种物理假设。真实抓握若经测试在特定负载范围内几乎不滑，可以在该范围近似为固定连接，但当前还没有这项实证。

## 2. 第一项问题：需要控制哪些相对运动

### 2.1 先区分“手在乱动”的来源

| 现象 | 可能机制 | 应采取的措施 |
|---|---|---|
| 指关节被撑开、指腹压缩 | 有限夹紧力、关节/软材料顺应 | 标定闭合控制和持续承载能力，限制载荷 |
| 手沿横杆滑动或绕杆转动 | 摩擦不足、接触几何不利、力矩需求过大 | 测量方向性承载范围，调整抓姿及任务力/力矩 |
| 双臂来回顶、抖动 | 两侧位置目标不一致、执行延迟或过高刚度 | 协调双臂目标，限制残差速率，调节有关方向的刚度和阻尼 |
| 手与车相对位置持续变化、接触消失 | 失稳滑移或脱手 | 降低推车需求、稳定停车；重新抓握作为后续单独能力 |

小幅、可恢复的相对运动未必是失败。真正需要限制的是失稳滑移、持续漂移、夹持力不足以及不必要的内部载荷。材料或握持衬垫若用于实机，应同步纳入仿真和标定；不能依靠虚构的大摩擦系数。

### 2.2 推荐的物理与控制结构

1. **恢复手—杆接触。** 使用实际横杆尺寸、手掌/指面的碰撞体、可动手指、质量、关节限位及有限驱动力矩。去掉对应的永久固定连接，同时启用必要接触对。只删 weld/FixedJoint 不够，当前手和杆的接触几何也不齐全。
2. **手指使用独立抓握控制。** 先选择固定抓姿和闭合目标，通过硬件实际支持的有限力矩位置伺服，或经确认可用的电流/力矩接口保持抓握。暂不增加高层手指动作维度。持续力矩、响应速度和增益要与实机匹配。
3. **双臂目标共同服从把手运动。** 减少两侧互不相容的位置残差；对沿杆、绕杆等易产生无效内力的方向研究有限顺应，对推车所需方向保留足够控制能力。方向及参数由试验决定，不是统一把所有 PD 调低。V6 当前手臂目标残差可达 ±0.4 rad，这一范围不应未经检查直接继承到真实抓握。
4. **先被动顺应，再验证主动导纳。** 可先通过匹配的有限刚度/阻尼和较小的目标变化改善交互。只有载荷估计经过独立验证后，才将它用于快速受力反馈或主动导纳；旧固定连接下训练的力头不宜直接承担这一职责。
5. **接触监测独立于路线奖励。** 记录每手轴向滑移、绕杆转角、接触持续性、指关节偏差及执行器饱和情况。初期采用失去稳定抓握后受控停车，自动重抓另行训练。

直观上，应让可提供压缩支撑的掌面/指面分担主要推力，减少单靠指尖切向摩擦或腕部扭矩维持运动的需求。这必须结合实际抓姿验证；对于某一载荷方向是否形成几何支撑，不能只凭手看起来包住横杆判断。

### 2.3 当前“手部力估计”不能回答抓握是否稳定

V6 双手头输出每手掌原点处的 `[Fx,Fy,Fz,Mx,My,Mz]`，沿小车航向及世界竖直轴表达，方向为手对车。它是**合力/合力矩**，不是各指接触法向力、夹紧力或摩擦余量。

例如，两指相对挤压横杆，夹紧力很大时，两侧法向力仍可能在合力中抵消。因此，相近的手部合载荷可以对应完全不同的夹紧程度和滑移风险。双手之间也可能有相互抵消的内部载荷，小车总推力不大并不代表两手轻松。

训练标签来自 incoming joint wrench 减去手子树 Newton–Euler 惯性/重力项；它是依赖仿真模型的监督标签，源码明确没有宣称独立力传感器真值。真实可动手指加入后，需要核查子树、惯量、参考原点和接触力合成，再重新训练/验证估计器。旧模型的 118/132 N 峰值只表示旧场景需求，不能当作 Dex3 能力上限或抓握验证结果。

### 2.4 建议先做的小实验

先做单手与实际横杆的固定台架实验，再做双手共同握杆。按实际推车需求逐步加载：前后推拉、沿杆侧向、上下、绕杆转动和偏心力矩。记录位移/转角、各指状态、电机信号及已知外部载荷；比较持续承载与短时峰值。

目标是得到“在此闭合目标、材料和抓姿下，哪些载荷组合可以持续保持、何时开始滑动”的范围，而非一个脱离方向的最大 N 数。用部分加载条件标定接触模型，保留其他条件检验预测。之后接入全身系统，按站立、低速直推、启停、转弯、增加载荷的顺序验证。

完整手指接触若使大规模训练过慢，可以用上述数据拟合允许粘着、滑移和脱开的等效模型。等效模型需要有方向性、有限承载、抓握状态和脱开后不再跨间隙传力的机制，并在详细接触场景与实机台架上复核。简单换成一个永不断开的六维弹簧仍会保留关键错误。

### 3.2 小车究竟需要什么

**当前 V6 策略外部输入中，直接与小车有关的是相对 yaw 和质量参数。**

- 相对 yaw 定义为 `wrap(小车世界航向 - 机器人基座世界航向)`，单位 rad。它不是摄像头里的横杆倾角，也不是左右手连线的朝向。实机可以通过车上的视觉标记和机器人相机获得相对姿态，结合相机外参、机器人运动学及重力方向换算。两套独立 IMU 的 yaw 不会天然同零点、无漂移。
- 质量字段的严格代码语义是 `cart_base_kg + payload`，归一化 `(m-12)/25`。目前 `cart_base_kg=12 kg`，该量写入车根刚体，并非对包括轮子/脚轮的全部小车刚体求和。实机称重和仿真参数应使用一致定义，不能只看变量名 `cart_mass_total`。
- 真实把手 xyz 已按 V6 设计从 actor 和两个估计器输入中删除。
- 小车速度 `[vx,vy,wz]` 由车速 HIM 估计。`vx,vy` 是车根刚体 COM 速度在车头航向坐标中的分量；`wz` 是世界竖直角速度。标记点/把手点速度与该参考点不同，转弯时需做刚体速度换算。
- 双手 12 维合载荷由力头估计，也不是外部直接测量输入。

车速 HIM 的输入为 `(HOMIE76 + 相对 yaw1) × 6 = 462`，不含上身力矩、质量和指关节状态。车速监督对应下一控制采样点，当前为 20 ms 预测步长。力头输入为 605 维历史加预测车速，输出当前采样的双手载荷。Actor 再接入预测速度 3、HIM latent 32 和双手载荷 12，合计 652 维。

**没有要求输入真实车速，不等于真实车速在滑移情况下仍可被准确推断。**

在同一世界坐标系中，手上跟踪点与车上固定参考点的运动可写为：

`v_hand = v_cart + omega_cart × r + v_relative`

固定连接近似令相对运动项为零。真实滑动使其未知；机器人自身运动和相对 yaw 可以相近，而车的平移速度不同。历史网络能利用训练分布改善估计，但不能保证一般滑移工况下唯一恢复这些量。加入真实接触后，必须重新检查车速头的误差，特别是启动、刹停、单手滑移和转弯阶段。

建议首轮实机实验使用独立的小车视觉/运动测量作为验证依据；若误差表明仅靠当前历史不足，再增加可部署的速度或相对运动观测。相对位置本身也需要与机器人运动估计结合才能得到车的绝对速度。只用车轮编码器，在万向轮转向和打滑时同样需要额外模型与验证。

### 3.3 上身力矩是明确的部署缺口

训练侧来源是 `robot.data.applied_torque` 的上身切片，不是手部六维力传感器。仓库内 `body_control_data_lcmt` 只有 `q[29]`、`qd[29]` 和时间戳；C++ 桥接也只转发这些电机量。

本地 SDK 的 `MotorState_` 定义有 `tau_est`，说明存在候选接口；但字段存在不能证明当前硬件的数值精度、延迟或可用频率。实机需要实际读取，核对单位、符号、关节映射、偏差、滤波和饱和，并在训练中反映这些误差。用 `Kp(q_target-q)-Kd*dq` 直接替代该字段也不是已验证的等价替换。

本地手部消息还定义了 motor state 与 pressure sensor state，但当前 27 关节 HOMIE 观测不包含它们。Dex3 实际可读取哪些反馈，仍需按用户设备版本与运行接口确认，不能据消息定义假定完整触觉可用。

### 3.4 策略之外还存在小车观测依赖

当前 bench 路径跟踪器每步调用 `policy.pose()` 和 `policy.velocity()`；V6 继承的实现直接读取仿真小车 `(x,y,yaw)` 与真实 `(vx,vy,wz)`，据此生成速度命令。

- 如果只是手柄下发速度、测试低层推车，任务命令不依赖这套循迹器。
- 如果要复现当前自动跑 S 弯/路线，必须为外层提供小车在路线坐标系中的位姿和所需速度估计，或重新设计外层控制器。相对 yaw 单独不足以运行现有外层循迹闭环。

当前距离、倾斜等仿真终止判断也使用小车状态。实机接触监测和停车逻辑应有自己的传感来源，不能把仿真 reset 当作已经实现的实机保护。

Critic 和监督标签中的脚轮转角、摩擦、载荷 COM、真实速度与真实/代理载荷属于训练信息，不需要为了 actor 部署逐一加传感器；质量字段则确实已经进入 actor，不能误列为纯特权量。

## 4. 推荐的推进顺序与验收依据

1. **确认硬件接口并记录数据。** 机器人 IMU、27 关节 q/dq、上身 `tau_est` 候选、Dex3 指关节/执行器反馈及相对 yaw 来源。先测实际时间戳、延迟与丢帧。小车已知质量也明确为输入条件。
2. **完成手—杆台架标定。** 找到可重复保持的抓姿、闭合目标和方向性承载范围。若所需负载超过实测能力，优先改变抓姿/接触表面或降低加速度、载荷与转弯需求，不能期待 RL 突破硬件限制。
3. **建立独立接触场景。** 复现实测滑移与释放，使用独立加载条件检验。旧 V6 固定连接场景保留作比较。
4. **接入冻结 HOMIE 做低速验证。** 检查双臂目标冲突与接触持续性，再决定是否需要推车工况的低层微调；不能预先保证冻结 HOMIE 足够。
5. **在新接触分布中训练高层和估计器。** 用独立测量对齐验证车速与每手载荷，同时评估滑移、持续饱和、接触丢失和任务跟踪。持续承载阈值来自硬件实验，不从旧焊接峰值倒推。
6. **完成整条闭环观测来源。** 自动循迹还要验证外层位姿/速度；明确视觉丢帧时的行为。当前 V6 只有有噪声/有限延迟的相对 yaw，没有视觉有效位或丢帧输入；若改变接口，应作为新版本训练和导出。
