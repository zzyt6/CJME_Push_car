# V5.1 升级方案：固定抓握下的交互估计与学习恢复

> **2026-09-25 实施更新：** 已建立独立 V5.1 训练入口，接入历史编码器、载荷辅助损失、FK 观测及含实际外扰的 Critic。可运行命令、验证记录和仍未覆盖的范围见 [V5.1 训练说明](push_cart_v51_training.md)。下文保留设计阶段原文；关于“尚未实现”的描述以训练说明为准。

日期：2026-09-24。状态：**代码审查后的待实施方案**。本次只新增方案并在旧总方案中标注入口，没有修改训练代码、启动训练或取得新的性能结果。

核心调整：**利用固定抓握建立可实现的运动学观测，复用已有运动估计，学习交互载荷及其对动作的影响；物理主要负责仿真、监督标签和实验解释。** 不再把整套全身动力学审计、名义力控制和四项新物理代价全部作为日常 PPO 的默认依赖。

原 `homie_pushcart`、现有 V5 revision 2 的入口和检查点应继续可运行。后续实现采用独立版本、配置和日志目录，不能把旧模型直接当作新观测接口的模型加载。

## 1. 对当前问题的明确回答

| 问题 | 核查结论 | V5.1 决定 |
|---|---|---|
| 把手不是固定的吗？ | 是。Isaac 是 palm—cart base 的六自由度 FixedJoint；MuJoCo 是 wrist—cart 的 weld。固定的是手与车，不是车与骨盆。 | 在固定抓握假设下直接用腰和手臂运动学恢复车相对身体的位姿；不要求新增视觉。 |
| 车的质量和质心重要吗？ | 会影响惯性、稳定性和真实响应；但不等于 Actor 必须知道它们。 | 保留仿真中的质量、惯量、载荷偏置及随机化；取消 Actor 中依赖真值的质量输入，不把质量/质心辨识作为主线前置任务。 |
| 能用以前的估计器吗？ | HIM 估计基座线速度；已有运动跟踪器结合相对把手位姿、HIM 和 IMU 检测运动。它们没有输出可解释的载荷质量、质心或手力。 | 复用 HIM、历史缓存和运动滤波；改用 FK 输入。交互力需要新的学习分支，不能把 HIM latent 直接改名为力。 |
| 上身力矩先从仿真取可以吗？ | 可以作为当前实验的明确假设。当前代码本来就读取上身执行力矩。 | 继续保留，加入偏置、延迟和缺失对照；不阻塞仿真实验。最终部署再对接电机反馈/力矩估计，当前 LCM 接口尚未提供这些力矩字段。 |
| 新增物理计算是否过量？ | 是。收益尚未证实，却在每个物理步执行全身、整车、足轮接触与冲量审计。 | 训练和物理审计分开；先删掉不需要的计算依赖，再考虑必要计算的优化。 |

需要撤回的设计假设：**目前的“仿真质量乘 ±10% 误差”不是质量估计器；“车位姿真值加延迟和噪声”也不是固定抓握运动学。** 两者都不能作为已经打通部署观测的证据。

## 2. 观测：固定抓握已经提供了什么

令 $B$ 为骨盆坐标系、$P_i$ 为左右手掌坐标系、$C$ 为车体固定几何坐标系：

\[
{}^B T_C^{(i)}(q)={}^B T_{P_i}(q)\,{}^{P_i}T_C.
\]

其中，第一项由**测得的腰部和手臂关节角**计算，第二项是已有抓握标定中的固定变换。不能用关节目标代替测得关节角，也不能只用两手位置的平均值代替完整旋转标定。

现有 `pose.py:Kinematics` 可作为标定和数值验证基准。4096 环境在线使用缓存关节链的批量 Torch FK，不逐环境调用单实例 NumPy/yourdfpy。编码器零偏、测量噪声、同步延迟和抓握标定误差作用于这条观测链，不能先读仿真车位姿再给输出加噪声。

左右手分别推算车位姿，融合时正确处理旋转，并保留闭链不一致指标。仿真约束有数值误差；实机若发生抓握滑移，固定变换会失效。初期研究限定可靠固定抓握，闭链异常时降低动作权限并标记观测无效；不能声称 FK 对任意滑移都有效。

把手点 $H$ 的速度可以按下式构造：

\[
{}^B\hat v_H={}^B\hat v_B+{}^B\omega_B\times{}^B r_{BH}
+{}^B\dot r_{BH},\qquad
{}^B\dot r_{BH}=J_{H,B}(q)\dot q.
\]

基座速度复用 HIM，角速度来自 IMU，相对速度来自关节运动学。已有运动跟踪器的缓存和滤波可复用，但其移动坐标系中的滑窗近似必须核查；不能直接称为精确车速传感器。HIM 在推车载荷下也可能偏差，须用仿真真值作离线验证。

从把手换到车体几何点必须使用**车体角速度**，包含手臂相对身体的运动：

\[
{}^B\hat\omega_C={}^B\omega_B+J_{\omega,P_i/B}(q)\dot q,
\qquad
{}^B\hat v_C={}^B\hat v_H+{}^B\hat\omega_C\times{}^B r_{HC}.
\]

固定抓握使手掌与车体具有相同角速度；不能直接用基座 IMU 角速度代替车体角速度。这里所有速度均相对世界运动、表达在当前骨盆坐标系，位置差和雅可比使用相同坐标。

**任务参考点统一为车体固定几何点 $C$，而非随载荷变化的整车 COM。** 由把手点到该点的几何偏移已知，速度换点包含角速度叉乘项。当前 V5 的 `cart_state()` 返回车体位姿、整车 COM 线速度、车体角速度，语义混合；实施时必须显式拆开。新指令、奖励和评测统一使用几何点；旧 COM 指标作为附加记录，所有参与比较的基线在同一新协议下重测。

### Actor 的输入约定

| 输入 | 来源 | 处理 |
|---|---|---|
| 关节角、关节速度，IMU 角速度和重力方向 | 本体传感 | 保留 HOMIE 已有输入约定；不重复生成不一致的噪声副本。 |
| 任务参考、实际下发命令、上一动作/控制目标 | 控制器已知 | 保留；指令不能暗含未知质心位置。 |
| 基座速度估计 | 冻结 HIM | 保留；latent 仍没有预先定义的质量/力语义。 |
| 把手/车体相对位姿、几何点运动估计 | FK + IMU + HIM | 替代真值 pose 加噪声；所有坐标变换同样使用这条估计链。 |
| 15 维上身关节力矩 | 当前仿真执行力矩 | 当前允许的代理输入；后续对齐实际反馈接口及误差。 |
| 交互历史编码及预测载荷 | 新的因果学习估计器 | 仅由上述输入及历史生成，训练与部署采用相同推理链。 |

Actor 不读取真实载荷质量、整车 COM、惯量、足轮摩擦、真实接触扳手、真实扰动时刻或真实车速。仿真真值可用于奖励、辅助监督和 Critic。Critic 保留已有且计算便宜的状态，不为提供额外几维输入而强制开启全身动量/足轮扳手计算。

新观测的维度、归一化、时间戳、历史长度和版本在实施时统一定义并检查。不能沿用“141×5”的旧标号却改变字段含义，更不能把删除的特权量填零后宣称旧模型行为等价。

## 3. 主线方法：学交互与协调，不再预先算出补偿动作

建议主研究候选采用**带物理监督的历史交互编码器**，同时建立一个无力监督的历史策略基线：

\[
z_t=E_\theta(o_{t-k:t}),\quad
\hat W_t=g_\theta(z_t),\quad
[\Delta u_t,\Delta q_{upper,t}]
=\pi_\theta(o_t,z_t,\hat W_t).
\]

编码器从关节运动、力矩、基座响应和控制历史中学习当前交互状态。先预测把手中心、车朝向坐标中的三维平面合载荷 $\hat W=[\hat F_x,\hat F_y,\hat M_z]$。统一采用机器人作用于车的符号；同点同坐标下车对机器人的反作用取反。不把“精确辨识双手各自六维力、车质量和质心”同时设为前提：闭链内力和模型误差会影响可辨识性。

该预测是**总交互载荷估计**，包含有用推力，不能称为“有害反力真值”。估计器输入不使用仿真手力；训练也让 Actor 使用预测量，不先喂真值再指望部署时无损替换。编码器、预测头和高层 Actor 都可训练，仅 HOMIE/HIM 冻结。

力标签拟采用经过 Newton–Euler 补偿的手子树扳手，两手统一坐标并换算到已知把手中心。**当前动态标定标志仍为 `dynamic_contact_wrench_calibrated=false`，它是待验证的仿真载荷标签估计，不是已证实准确的传感器真值。** 预热完成和数值有限不等于动态标定通过；正式辅助监督前先在 audit 中验证符号、参考点和动态误差。不为提速退回“只减重力”的旧代理。通过核验后用当前总载荷标签训练，不引入需要精确阻力辨识的“名义推力残差”标签。监督采用按量纲归一化的鲁棒误差，检查相位延迟、动态误差和未见载荷泛化，不能只看平均拟合误差。

历史长度先以约 0.4 s 的小型因果编码器为候选，与原五帧历史比较；它是待验证的设计值。所有对照共享可部署输入、网络容量和历史预算，避免把更长记忆的收益写成力监督的收益。若显式力预测不提高任务/恢复效果，保留历史适应，不强行保留该分支。

执行仍为 **3 维速度残差 + 15 维上身残差**，共同 PPO 训练。默认关闭名义扳手模型驱动的解析速度补偿；保留必要的坐标换算、限幅、限速及 HOMIE 指令范围。解析补偿只作为独立消融分支，不和估计器一起默认叠加。

**静止恢复权限必须同时修正。** 现有按指令大小缩放全部残差的门控会在零指令时关闭动作；旧 idle tracker 只在曾经运动后的一段时间内开启。V5.1 用 IMU 倾斜/角速度和可观测运动偏差触发有界恢复权限，加入滞回与静稳退出。持续偏差存在时不能只因固定计时结束就关闭权限；也不能永久全幅打开导致静止漂移。此门控只决定允许多大动作，不依据真实外扰时刻，也不手写恢复方向。

## 4. 物理到底保留在哪里

物理模型多少与创新强弱没有直接关系。应保留能说明目标、构造监督或验证机制的部分；策略负责在冻结底层运动接口下学习时序协调。

| 项目 | V5.1 默认位置 | 原因 |
|---|---|---|
| 真实质量/惯量、固定抓握、脚轮、摩擦、PD 和外力作用点 | 仿真动力学 | 决定交互是否真实；不能为了提速删掉惯性或改成直接改车速。 |
| 抓握几何、速度/力矩参考点换算 | 观测、标签和评测 | 成本可控，避免把正常转向误判为扰动。 |
| 局部手子树力学校正 | 训练所需标签、过载检查和审计 | 监督要可信，但不要求同步求完整机器人动量。 |
| 名义质量—阻力模型及解析补偿 | 非默认消融 | 目前需要未知参数，残差混合模型误差，还可能与 RL 动作竞争。 |
| `task_wrench` | 非默认消融/诊断 | 偏离名义推力不等于有害反力，可能惩罚必要施力。 |
| `reaction_motion` | 诊断优先 | 运动偏差不等于反力的因果影响，且与任务/姿态指标有重叠。 |
| `centroidal_recovery` | 小规模审计/单独消融 | 当前目标未匹配步态相位，可能压制合理恢复动作。 |
| `support_feasibility` | 小规模审计/单独消融 | 足底接触查询较重，当前 CoP/摩擦近似也不是完整可行性保证。 |

日常奖励以已有**任务跟踪、对称进度、停车、执行器/关节限制、腕部负荷、抬轮、几何距离和跌倒**等为基础，保留弱动作正则。已有低成本速度质量项先维持作为受控对照，不同时大改全部权重。

四项新物理代价默认关闭；`force_waste`、无差别的手力变化惩罚和手力频带惩罚也不作为主线默认项。竖直力、左右差动力和短暂增力可能服务于支撑、转向与恢复，不能一律算浪费。`cart_yaw_lead` 也移到单独消融：当前定义可以通过增大身体转向误差获得奖励，不能把它等同于车跟踪更好。

`force_budget` 可暂作超阈值负荷正则保留用于可比实验，但当前 `30 + 2×质量` 的阈值是经验设置，**不是执行器安全边界**。实际力矩饱和、跌倒和数值故障检查保留。之后单独检查这个经验预算是否限制必要推力，不把所有手力压向零，也不把奖励阈值当论文达标标准。

## 5. 提速：训练不再承担全量审计

代码审查发现：当前每 5 ms 调用全机器人/整车动力学、两脚四轮的逐接触扳手，再记录全量物理样本和冲量；部分状态在奖励与观测更新时重复计算。**把奖励权重设为零不会自动停止这些调用。**

建议拆出三个明确模式，名称是待实现接口：

| 模式 | 计算范围 |
|---|---|
| `train` | 保持 200 Hz 物理积分、50 Hz 控制；FK、HIM、高层策略、必要奖励、局部手力校正和故障检查。关闭全量物理轨迹复制、动量闭合、轮地扳手及非必要足底逐接触计算。 |
| `labels` | 选定环境记录可观测历史、时间戳和同步力标签；需要研究快速冲击时保留高频标签。辅助学习也可消费训练中已计算的有效手力，不另开整套审计。 |
| `audit` | 少量环境完整记录手力、足轮接触、全身动量和冲量，用于校验物理闭合及论文机制分析。 |

先做不改变采样语义的优化：手校正只取局部子树；缓存同一时刻重复状态；按依赖跳过关闭的诊断。初版保留必要手信号的 200 Hz 采样和故障检测，避免遗漏短冲击。之后再独立评估 50 Hz 末端标签是否够用；末端样本不等于区间平均，降低采样不能继续宣称记录了完整冲击峰值。

关闭轮/足审计时，要拆开手力、接触、数值故障的有效性条件；不能因轮查询关闭而把手标签全部判无效，也不能用全零数据冒充有效测量。Critic 同步删除对应字段。缓存遇到 reset、质量或质心随机化必须失效。

已有历史日志显示采样阶段约从 V4 的 2.50 s/iteration 变为 V5 的 11.66 s/iteration（4096 环境，24 步 rollout）；PPO 更新仍远短于采样。两次训练课程和配置不同，这不是受控速度实验，不能由此精确归因或承诺提速倍数。正式比较固定环境数、课程、种子、物理步长与记录频率，分别报告采样时间、PPO 时间、FPS、显存及峰值信息是否保留。

## 6. 环境升级与论文证据

环境重点增加**可控载荷变化及解除后的恢复**，无需先升级成在线全身优化控制器：

1. 持续推车：不同载荷、重心偏置、脚轮初始朝向与滚动阻力，测试同一任务下的适应。
2. 阻力建立—保持—解除：轮阻尼/阻力真实变化，观察解除后的冲车、前倾和恢复；不是直接覆盖车的状态。
3. 已知时刻、方向、幅值和作用点的车侧力脉冲；机器人本体推扰单独设置，区分耦合恢复与普通站立抗扰。
4. 初始静止受扰、停车后受扰、持续受力超过旧门控时间：专门检查恢复权限是否真实有效。

保持基本可完成任务与低扰动样本混合，随后逐步扩展扰动；课程可以先用扭矩余量做保守量级筛选，再通过仿真检查可完成性。不能只凭静力近似的 $J^T F$ 限矩就宣称包含惯性、支撑与所有接触的全身可行性。

最低必要对照：

| 对照 | 回答的问题 |
|---|---|
| A：现有 V4/V5 模型在统一新几何点协议下重测 | 原模型处于什么水平？历史数字不能直接移用。 |
| B：可部署观测 + 等容量历史策略，无力监督/解析补偿 | 本体历史是否已经足够？这是主学习基线。 |
| C：B + 交互力预测及辅助监督 | 物理监督是否真正改善适应与恢复，而不只是多输入/参数？ |
| D：C 的上身固定/仅速度残差消融 | 上身与速度联合协调是否有独立贡献？仅在消融中固定上身。 |
| E：按结果选择解析补偿、单项物理奖励、无力矩输入等对照 | 额外物理模块或力矩反馈的收益是否值得成本？不要一开始做全组合。 |

主要指标同时包含任务速度/转向误差、实际进度、跌倒率、扰动与解除后的误差积分、超调、身体倾斜/角速度以及恢复时间；手力峰值/冲量和关节饱和作为负荷与机制指标。完整动量、CoP 等在 audit 中辅助解释。

恢复定义为重新进入任务和姿态容差并连续维持一段时间；受扰开始和外力解除分别计时。始终未离开容差带的回合单列为扰动抑制成功，避免与离带后的恢复混淆。容差先依据传感/估计误差、无扰基线波动及实际任务要求制定，在独立测试前固定；未恢复及跌倒必须计入失败，不能只统计成功回合的恢复时间。

配对使用相同指令、载荷和外扰序列，同时报告无扰与受扰结果及其差异。只有任务完成质量相当且实际运动没有被策略压慢时，才讨论反力影响减小；不能用手力更小单独证明“抵消”。这种实验量化的是闭环性能损失与恢复，不把名义模型残差包装成已分离的有害反力。

最终研究主张是候选：**在冻结基础运动技能和固定抓握条件下，用本体历史及物理监督得到交互表征，学习上身—速度协同，改善载荷建立与解除时的任务保持和恢复。** 其中每部分都需要对照证明；不是因为公式多或少就自然具有创新。

FALCON 可支持“本体历史能够用于交互适应”的路线，但它的上下身联合训练与本项目冻结 HOMIE 不同；不能把本方案称为完整 FALCON 复现，也不能把它概括成必然包含显式六维力估计器。已核查文献及边界见 [研究计划](push_cart_reaction_recovery_research_plan.md) 和 [FALCON 正式论文](https://proceedings.mlr.press/v331/zhang26a.html)。

## 7. 实施顺序与验收

1. **独立实现 V5.1 观测与参考点。** FK 和运动估计与仿真真值对齐，包含腰转、手臂运动、转弯和不同载荷；检查 Actor 及其坐标变换不存在真值旁路。保留旧入口，新版本记录完整观测 schema。
2. **拆训练/审计依赖并测速度。** 先固定动作序列，比较必要端点状态、手力标签、故障与 reset 处理；再做小批闭环。区分预期设计变化和计算优化，不要求新旧奖励完全相同，却要求缓存/采样优化不偷偷改变各自定义。
3. **建立 B 学习基线，标签动态校验后再实现 C。** 力预测的标签同步、坐标、因果历史和辅助梯度在短验证中查正确性；PPO 策略内编码器按相同历史重算，不能使用训练时的未来数据。若标签校验失败，继续历史策略基线并修正测量模型，不用错误标签强行监督。主实验两组获得相同样本预算、课程分布与网络预算。
4. **充分训练后评估。** 120 轮只做运行检查。可沿用 4096×24×20000 作为首轮预算上限，每 500–1000 轮评估固定验证集；以学习曲线和未见工况表现判断是否需要继续，不能用轮数本身证明收敛。最终关键对照至少 3 个种子，同时报告样本量与墙钟成本。

本次没有新增训练命令，因为上述模式、观测接口及力学习分支尚未实现；现有 V5 命令仍运行旧的 revision 2，不能用新方案名称描述它的训练。
