## 1. FALCON 实际使用什么力

核对官方仓库固定提交 `a967a6d8494f57777cf8d266a644ac8e45833301`。本地原文和源码保存在 `.cache/falcon_reference/`。

| 路径 | 可直接核验的行为 |
|---|---|
| [论文附录 A.3](https://arxiv.org/html/2505.06776v2#A1.SS3) | 三维末端力估计器，输入五帧全身关节位置/速度、根角速度、投影重力及过去下肢动作；明确写出 “compare the estimated and applied forces”。这是显式估力对照，不等于 FALCON 主方法的全部双策略训练。 |
| [训练力构造，L259–340](https://github.com/LeCAR-Lab/FALCON/blob/a967a6d8494f57777cf8d266a644ac8e45833301/humanoidverse/envs/decoupled_locomotion/decoupled_locomotion_stand_height_waist_wbc_ma_diff_force.py#L259) | 构造左右手施加力，保留其数值；`left/right_ee_apply_force` 是该世界系力旋转到基座坐标系的值。每个物理子步调用外力接口。这里的 `max_force_estimation` 是可施加力范围计算，不能当作神经估力器。 |
| [力作用点，L524–530](https://github.com/LeCAR-Lab/FALCON/blob/a967a6d8494f57777cf8d266a644ac8e45833301/humanoidverse/envs/decoupled_locomotion/decoupled_locomotion_stand_height_waist_wbc_ma_diff_force.py#L524) | 作用点由手链接位置与扩展末端点插值得到，并单独传入外力接口。 |
| [训练外力接口，L487](https://github.com/LeCAR-Lab/FALCON/blob/a967a6d8494f57777cf8d266a644ac8e45833301/humanoidverse/simulator/isaacgym/isaacgym.py#L487) | Isaac Gym `apply_rigid_body_force_at_pos_tensors(..., ENV_SPACE)`；并非读取推车抓握反力。 |
| [MuJoCo 估力测试，L44–51](https://github.com/LeCAR-Lab/FALCON/blob/a967a6d8494f57777cf8d266a644ac8e45833301/sim2real/sim_env/loco_manip.py#L44) | `estimate` 分支把基座负 x 方向的已知力转到世界系，直接写入左右手 `xfrc_applied[:, :3]`。这一路径没有用车把 weld 反力构造参照。 |

公开代码中的施力/观测路径和论文能够支持上述结论；本轮未核验到附录 A.3 估力器的独立完整公开训练入口，因此不声称逐行复现其训练。MuJoCo 分支也不证明它与训练端的每个作用点、时序和场景参数完全相同。

**应更正的方法称谓：当前估力网络参考了 FALCON 的本体历史输入；此前的推车训练和测试没有完整复现 FALCON 的“已知施加外力”验证任务。**

我们的标签定义是双手各 6 维的手对车 wrench，包含内力和手掌力矩；FALCON 上述施力变量表达环境对机器人的力，并采用基座坐标系。直接移植还需要处理正负号、参考点、坐标轴和时间定义，不能只把标签 API 换个名字。

## 2. 两种标签算法是否已经把力算错了

来源不同不必然代表物理量不同。Isaac 的手子树平衡与 MuJoCo 的约束重建都可以表达手对车的力；问题是要分别校验，还要保证产生这些力的物理场景可比。

### 相同已知手部外力

MuJoCo 新探针复用既有 Isaac 探针的六阶段施力函数：零载、正负静载、运动零载、动态加载和卸载。两个初始航向、左右手分别记录，5 ms 采样；每引擎 2,400 个采样时刻，共 9,600 个手部样本。冻结 HOMIE 继续控制下肢。

两端施力时序的最大差为 0，施力值最大差为 `2.373e-7 N`。MuJoCo 使用手臂逆动力学重建，不读取已知手部力数值作为重建输入，也不读取约束反力；已知施加力只作为独立参照。

| 重建路径 | 跨阶段/环境/手的最大力向量 RMS | 最大力矩向量 RMS |
|---|---:|---:|
| Isaac 手子树标签 | 0.002714 N | 0.000471 N·m |
| MuJoCo 手臂逆动力学 | 6.80e-14 N | 6.40e-15 N·m |

**这些是标签重建误差，不是网络预测 RMSE。** 载荷仅为数牛量级，没有连接车；不能据此宣布真实推车闭链或大载荷标签全部正确。MuJoCo 浮点精度级结果也不等于该引擎与现实物理一致。

### 车侧独立平衡

新增左手单抓握、右手单抓握、双手抓握三个 Isaac 诊断场景。把系统移离地面，关闭重力和刚体阻尼，用预先规定的目标和车身外载荷激励。通过**车全部刚体的质量、加速度及惯性**求解车所需外力，与手部标签合成值比较；参照不读取掌部 incoming wrench。

| 场景 | 合力平衡残差 RMS | 合力矩平衡残差 RMS |
|---|---:|---:|
| 仅左手 | 5.91e-6 N | 0.02346 N·m |
| 仅右手 | 5.83e-6 N | 0.02375 N·m |
| 双手 | 1.98e-5 N | 0.01849 N·m |

三个场景各 380 个物理样本，全部有效、无重置、脚部接触力为 0，车体最低高度超过 3 m。结果支持掌部标签的基本力平衡，但不能用双手合力平衡排除相互抵消的逐手误差；这也是保留单手测试的原因。力矩仍有数值残差。

首次 `cart_label_balance/` 诊断明确为无效执行：为改变抓握拓扑而关闭场景复制后，环境原有的 env_0 属性覆盖不再传播到其他副本，导致残留重力及后续接触/重置。修正诊断器逐副本设置属性后，另存 `cart_label_balance_recheck/`；补录真实关节状态和目标的最终版本为 `cart_label_balance_matched/`。失败数据和日志保留，不参与结论。这是新诊断器的配置错误，没有据此修改训练环境。

## 3. 找到的主要物理差异：双手内力与 weld 柔顺性

对上述三个场景在 MuJoCo 中重放相同目标与车身外力，不使用高层策略或估力器。实际关节目标最大差 `8.00e-8 rad`，因此以下差异无需任何神经网络即可出现。

| 场景 | 标称 MuJoCo 与 Isaac 的逐手力向量 RMS 差 | 提高 weld 阻抗后 |
|---|---:|---:|
| 仅左手：连接手 | 0.753 N | 0.161 N |
| 仅右手：连接手 | 0.788 N | 0.197 N |
| 双手：左手 | 23.852 N | 2.758 N |
| 双手：右手 | 23.904 N | 2.766 N |
| 双手：两手合力 | 1.293 N | 0.284 N |

双手场景中 Isaac 逐手力向量 RMS 为 29.18 / 30.31 N，原 MuJoCo 为 6.97 / 7.49 N；提高阻抗后为 26.51 / 27.63 N。内力大部分在相加时抵消，所以“车的合力接近”不足以证明“左右手受力接近”。

![同目标、同外载荷下的左右手与合力](../logs/bench/v52_sim2sim_root_cause/dual_grasp_response.png)

原 weld 的 `solimp=[0.95,0.99,0.001,0.5,2]` 不是理想刚性固定关节。本轮只对两条 grasp equality 设置常数阻抗 `0.9999`，其余参数不动，命名为 `rigid_limit`。数值取自 MuJoCo 允许的阻抗上限，没有按网络误差搜索最优值。该预设先在无估力器的物理实验中验证，再进行网络评测。

[MuJoCo 官方求解器说明](https://mujoco.readthedocs.io/en/stable/modeling.html#solver-parameters)明确指出阻抗内限为 `[0.0001,0.9999]`；正值 `solref` 时间常数默认至少为两倍仿真步长。因此 `dt=0.005 s` 时写入 `solref=[0.004,1]`，也不能理解为实际采用 4 ms 的刚性约束。原始文档快照保存在 `.cache/falcon_reference/mujoco_modeling.rst`。

这组干预支持“抓握柔顺性是重要原因”，不证明 PhysX 与 MuJoCo 已完全数值等价。双手剩余约 2.76 N 的无策略响应差仍需与步进、刚体动力学和固定关节求解区别对待。

全输入网络逐手力分量 RMSE `[Fx,Fy,Fz]`：左手从 `[10.39,10.10,5.82] N` 降到 `[3.12,2.70,2.69] N`，右手从 `[11.04,8.97,5.00] N` 降到 `[3.06,2.65,3.08] N`。

![一个实际推车工况的逐手预测](../logs/bench/v52_sim2sim_root_cause/prediction_example.png)

### 后续实际推车动态检查

在保留车轮、地面接触和固定网络闭环控制的 Isaac 推车环境中，完成同一 12 工况的逐子步核查，共 19,200 个物理采样时刻，全部标签/接触采样有效，无工况失败。左右手掌的标签与各自肩部 incoming force 减去整条手臂惯性/重力负载的独立重建相比，各力分量 RMS 为 `0.00071–0.00179 N`，最大瞬时差 `0.00705 N`。这扩展了对真实推车条件下逐手力标签的内部一致性证据。

车侧全身平衡还读取四轮地面法向与摩擦力。全工况力分量残差 RMS `[0.0312,0.0340,0.1034] N`，力矩残差 `[0.2748,0.4528,0.0353] N·m`。力矩与少量瞬态仍有残差，不能将这项核验称为独立传感器认证。训练用快速手子树路径与完整路径的力值完全相同，力矩差 RMS 小于 `2e-7 N·m`。原始数据见 `walking_dynamics/`。

### 惯量差异的最终处理

当前机器人 USD 的部分惯量方向与 URDF 不同；车载荷设置先调用 `set_inertias` 再恢复旧 COM 姿态，会改变 PhysX 实际惯量，而且影响全部车体和车轮。隔离刚体施加三个方向已知力矩，确认 `get_inertias` 与实际角加速度响应一致（矩阵误差约 `4e-7 kg·m²`），并非读取坐标系误判。

已从组合后的训练 USD 导出 49 个机器人刚体和 9 个车刚体的质量、COM、主惯量和主轴，记录全部来源层及 URDF 的 SHA256。MuJoCo 按已验证的固定关节变换合并刚体；载荷更新复现现有 PhysX 的主轴替换顺序，包含偏心载荷与车轮。此举兼容已有训练域，未修改 Isaac 训练资产或 setter 顺序。未来若修正训练端 setter 顺序，应另建物理版本、重采数据和训练，不能继续将旧权重称为新域训练模型。

实际调用 Isaac `_randomize_cart`，测试 0/5/12.5/25/50 kg、居中及平面偏心共 20 组设置，兼容计算与原始 API 惯量张量最大差 `1.32e-6 kg·m²`。三组标准载荷、全部机器人与车刚体的运行时惯量核验最大差 `1.10e-6 kg·m²`。数据见 `cart_inertia_reset.json` 和 `runtime_parameters_physx_inertia_final.json`。该修正没有使所有估力分量继续下降，因此不能称它是已找到的大误差主因；它解决了已证实的物理参数不一致。

最终全输入头逐手力分量 RMSE 为左手 `[3.195,2.649,2.814] N`、右手 `[3.099,2.685,3.159] N`。同一网络与同一训练集的最新帧覆盖检查中，IMU 角速度超出训练 1%–99% 分位区间的标量比例由 `17.82%` 降至 `15.09%`，关节速度由 `8.77%` 降至 `8.31%`；分布差异依然存在。统计不代表独立轨迹失败率，也不构成各误差来源的因果占比。
