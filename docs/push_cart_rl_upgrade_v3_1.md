**V3.1 增量升级方案：以推车操作质量为主目标，利用交互力改善车的运动**

日期：2026-09-20。状态：首轮代码已实现并通过短时验证；尚未启动正式微调，新增奖励的训练收益尚未验证。

基线：`logs/rsl_rl/homie_pushcart/2026-09-18_06-37-12_v3e_full/model_12600.pt` 及其运行配置。沿用已经可行的冻结 HOMIE + 上层 18 维动作（3 维命令残差、15 维腰臂修正），从当前检查点分支升级。

**1. 目标优先级**

本任务的操作对象是车。主目标是按要求完成车的平移、转向、路径跟踪、停止和保持，同时减少运动纹波、超调、冲击及车体异常倾斜。手部受力是产生和调节这些运动的手段，也是判断操作质量的重要信号。

机器人平衡、抓握保持和关节能力构成任务可执行的约束。合理前倾、迈步、腰臂运动可以服务于推车；只要处于可接受范围，不能为了降低机器人姿态波动而牺牲车的运动质量。失衡达到影响任务可行性的程度时，必须限制或终止。

概念上可写为：在机器人与抓握约束内，优先完成推车任务，再优化车的运动质量和施力质量。实际 PPO 中现有终止条件与软惩罚只是近似实现这些要求，不构成严格的约束保证，还必须依靠独立验收。

**2. 当前基础和明确的升级对象**

V3 已具备速度跟踪、`track_progress`、`cart_yaw_lead`、静止闸、动作正则以及力预算、`force_waste`、`force_rate` 等机制。第一轮保留这些基础，不改变底层 HOMIE、动作空间及 actor 观测布局。

已有 bench：`s_large` 和镜像路径横向 RMS 约 0.028 / 0.025 m；`wz_p03` 在载荷 0 / 12.5 / 25 kg 下的原始转速纹波 RMS 约 0.107 / 0.115 / 0.120 rad/s。转向纹波是一个有数据支持的升级对象，身体摆动与该纹波之间的原因关系尚待测量。

依据：[路径报告](../logs/bench/v3e_12600_audit_path_20260918/report.md)、[阶跃报告](../logs/bench/v3e_12600_audit_step_20260918/report.md)。这些是 V3 基线结果，不是本升级的结果。

**3. 受力分析围绕车的运动建立**

先统一坐标系、作用点和正负号。设机器人作用在车上的第 i 个手部载荷为力 f_i 和力矩 tau_i，力矩参考点为 p_i，车及载荷系统的质心为 c_C：

```text
手对车的合力：F_hand = sum_i f_i
手对车、关于车质心的合力矩：M_hand = sum_i ((p_i - c_C) × f_i + tau_i)
平面任务载荷：W_task = [F_forward, F_lateral, M_yaw]
```

前后力、侧向力和偏航力矩分别联系到车的平移和转向；竖直力及横滚、俯仰力矩关系到车轮承重、车体倾斜和离地风险。当前测力点若在掌心，力矩转换就使用对应掌心位置，不重复加同一段力臂。

手部载荷不是车的全部外载荷。轮地作用、滚动阻力、万向轮转向阻力及重力等共同决定运动。因此，不能简单将手部合力等同于 m*a，也不能为所有载荷和路面指定一个固定“最佳推力”。应在相同任务与运动条件下，评价力是否有效、平顺，是否造成不需要的运动。

现有仿真约束已经产生手车间双向作用力。车对机器人的反作用载荷属于同一交互的另一端，可用于机器人约束监测；不另外施加一次反作用力。

| 工况 | 需要保留的施力 | 主要优化的车侧结果 |
| --- | --- | --- |
| 匀速直行 | 克服滚动阻力的持续推力，必要的方向修正 | 前后速度纹波、无指令横摆与偏航、路径误差 |
| 起步或提速 | 产生目标加速度的推力增长 | 响应时间、速度超调、冲击 |
| 稳态或变向转弯 | 净侧向力与偏航力矩、左右手差动推拉 | 转速纹波、转向滞后、摆尾、横向误差 |
| 减速停车 | 必要的反向力和制动力矩 | 停止距离、回弹、停车后漂移 |
| 轮阻变化或车受扰 | 随负载变化调整的推力/转矩 | 车速与路径偏离、恢复任务所需时间 |

两手合力为零不意味着没有效果：左右手一推一拉可能产生有效的偏航力矩。制动时负功也可以是任务必需。不能把所有反向力、所有左右手力差或所有负功都判为浪费。

**4. 核心升级一：直接评价车的运动平顺性**

保留现有低通跟踪奖励和 `track_progress`，候选新增项为车速跟踪误差的带限波动，而非恢复原始车加速度平方惩罚：

```text
e = [cart_vx - ref_vx, cart_vy - ref_vy, cart_wz - ref_wz]
e_osc = BandPass(e)
C_cart_ripple = sum_axis robust_penalty(e_osc[axis] / scale[axis])
```

速度与参考使用一致的坐标和采样口径，线速度与角速度分别归一化。先通过基线频谱、手部载荷和车速同步轨迹定位可改善的频段，不先指定一个未经验证的滤波频率。滤波边界和复位历史需要正确处理；命令变化也可能产生真实跟踪误差，起步阶段允许的变化范围应预先定义。

该项的目标是车真实运动更平顺。带限信号用于训练时区分可控波动与测量/接触噪声，不能代替原始车速验收，也不能只挑选改善的频段汇报。

V3 早期的加速度惩罚曾教出“不愿推车”，这仍是本项需要验证的风险。利用已经可行的 V3 微调、保留进度奖励、采用低权重和逐步启用可以降低风险，但不能保证消除。若车速跟踪、任务完成或完成时间退化，应降低/取消该项，而不是放松任务要求。

**5. 核心升级二：利用车侧合力与偏航力矩改善施力质量**

现有 `force_rate` 评价每手力的相邻帧变化；它没有显式区分两手组合后对车产生的平移与转向效果。新增分析应先构建车侧 W_task，并与车速/转速纹波同步记录。

若测量显示某类重复推拉或偏航力矩振荡对应车的多余运动，再单独试低权重的车侧任务载荷波动项：

```text
W_osc = BandPass([F_forward, F_lateral, M_yaw])
C_cart_wrench_osc = sum_component robust_penalty(W_osc[component] / scale[component])
```

这是候选正则，不是“力波动必然有害”的结论。负载变化、轮地扰动或补偿步态影响时，力的变化可能恰好维持车速稳定；若抑制它导致车运动变差，应取消或调整该项。不同坐标的时间变化要先统一，避免转弯时旋转坐标系制造假波动。

第一轮不为 W_task 设定固定目标幅值，不直接惩罚全部净推力或转向力矩。维持现有硬件/抓握相关力预算，分别记录每手载荷，避免两手相互抵消后掩盖单手过载。新项与 `force_rate` 的重叠程度及每秒惩罚贡献需要单独分析。

对无效内力继续保留现有 `force_waste` 作为基线，诊断它是否准确覆盖当前抓握几何下的无效对拉。更一般的内力判断需要看它对车产生的完整合力与合力矩，不能仅凭左右手不相等。第一轮不同时重写全部旧受力奖励。

**6. 车体稳定与机器人约束的处理**

保留并检查现有抬车、车轮离地、抓握过载等约束。车的竖直力会改变轮载和摩擦，不能笼统认定所有竖直力都无作用。若出现车体倾斜或轮载异常，针对相应后果调整，而不是要求四个轮子时时均匀承重。

机器人侧第一轮保留现有摔倒、关节/腕力矩及动作限制，增加必要的诊断。只有出现会影响持续推车的过度倾斜、滑移或失衡趋势时，再添加阈值型软惩罚。正常范围内的身体前倾、摆动、迈步不作为主要优化对象。

关于机器人质心的反作用力矩可作解释和约束诊断，不作为本轮主要新增奖励。完整足底 CoP、多接触支撑优化、底层腿策略适应等，不列为本次操作任务升级的前置工作。

**7. 测量与策略输入的最小准备**

当前 `sim_env.py::grasp_wrench()` 从关节传递力换算手部载荷并补重力。新增车侧合力矩前，做有针对性的正负号、坐标、作用点和动态残差检查。核对实际包装层的 joint frame 与 palm frame；只有重力补偿时还要检查手部惯性对动态测力的影响。

同时保留原始、滤波、裁剪数据；明确物理子步与控制步采样口径，避免复位制造假冲击。[PhysX 官方说明](https://nvidia-omniverse.github.io/PhysX/physx/5.6.1/docs/Articulations.html#link-incoming-joint-force)指出该接口报告关节传递力，使用 incoming joint frame，且结果是仿真步内的平均作用力。需核对实际版本与接口，当前并未确认存在坐标错误。

第一轮保留 actor 输入。已有本体状态、上肢力矩、相对车位姿与历史可以支持微调，真实仿真载荷继续用于奖励和 critic。如果证据表明策略对轮阻变化等反应滞后，再单独加入可部署的手部测力/估计力输入；需模拟传感噪声、延迟与偏置，并同步 Isaac、MuJoCo、导出和接口版本。部署没有的真值不直接放入 actor。

当前零命令闸维持无扰静止表现；如果后续要求主动抑制停车后的车侧扰动，再单独评估有限的受扰响应通道。不能假设只改奖励就能绕过动作闸。

**8. 消融实验与验收**

先固定 V3 策略采样车速、手部载荷、车侧合力矩及约束诊断。同步变化或相关性不能单独证明因果，应结合不同工况、已知轮阻/外扰事件及后续消融判断。

从同一 V3 检查点分支，在相同额外训练步数与任务分布下比较：

| 组别 | 变化 | 回答的问题 |
| --- | --- | --- |
| A | 原 V3 奖励继续训练 | 额外训练本身的收益 |
| B | A + 车速带限波动项 | 直接优化车运动是否有效 |
| C | A + 车侧任务载荷波动项 | 施力正则是否改善车运动 |
| D | 有效候选组合 | 两项是否互补，是否重复惩罚 |

先短程筛查，有效候选再用至少三个独立训练种子确认。所有组保留低速、静止、起停和转向样本。基线原检查点用于回归，A 组用于区分额外训练时长的影响。

主要验收指标：车的原始 vx/vy/wz 纹波 RMS、速度偏差、超调、转向响应、路径误差、停止距离、停车回弹与漂移、受扰后的任务恢复时间。施力均值、波动、峰值、每手过载和内力代理作为解释与辅助指标；不能只因力更小就宣布升级成功。

约束验收：任务成功率、机器人跌倒、失握、关节/腕过载、车体倾斜与轮离地。合理范围内的机器人姿态变化可以增加，不能仅凭机身 RMS 增大否定一个推车效果更好的策略。

测试覆盖载荷 0 / 12.5 / 25 kg、直线起停、正反转向、路径与镜像、轮阻变化和车侧扰动；37.5 / 50 kg 作为泛化单列。固定 follower、命令、初始条件、名义速度及弯道减速模式；同时记录实际速度，排除靠走慢获得较低纹波。

建议候选目标：重点转向工况的原始纹波 RMS 改善约 20%，速度跟踪、路径误差和完成时间相对 V3 原基线原则上恶化不超过 5%，停止距离和静止漂移单独回归，近零量使用预先约定的绝对容差。这些是待验证提议，不是已经达成的结果；按工况报告，不用平均改善掩盖失败工况。有限测试中未出现新的失效也不构成绝对安全保证。

**10. 已实现的实验入口与参数**

旧 V3 默认配置中，两项新奖励权重均为 0，训练质量滤波默认关闭；旧检查点的 actor/critic 尺寸仍是 620 / 652，动作仍是 18 维。MuJoCo bench 会附加新遥测，但不修改动作或观测。

| `--quality_profile` | `cart_ripple` | `cart_wrench_osc` | 用途 |
| --- | --- | --- | --- |
| `diagnostic` | 0 | 0 | A 组：原奖励继续训练并记录新指标 |
| `ripple` | -0.05 | 0 | B 组：优先验证车的运动质量，建议首轮从此开始 |
| `wrench` | 0 | -0.02 | C 组：单独验证车侧施力波动项 |
| `combined` | -0.05 | -0.02 | D 组：验证组合是否互补 |

滤波采用世界坐标下两个一阶低通的差，输出再投影到当前车航向；初始候选参数为低截止 0.5 Hz、高截止 5 Hz，属于渐变频率响应，并非理想矩形频带。每回合用第一帧有效样本初始化，预热 1 s；新奖励在启动后的 60 s 环境控制时间内线性启用。这不是墙钟时间，也不随每个回合重新爬升。

速度归一化尺度为 `[0.05, 0.05, 0.10]`（m/s、m/s、rad/s），载荷尺度为 `[20, 20, 5]`（N、N、N·m）；均有小死区。Huber 成本按三个分量取均值，每项成本上限 4。完全启用时，两项新惩罚上限分别为 0.20 / 0.08 每秒，环境沿用原有乘 dt 的奖励积分。原始力矩保留在遥测中，只有奖励滤波输入做有限裁剪。

参数是实验起点。新基线的短窗 Welch 分析显示，运动工况转速波动主峰约 2.34 Hz，0.5–5 Hz 覆盖约 79%–96% 的转速波动谱功率，为候选频带提供了依据；这不证明施力波动的因果关系，也不证明该频段在所有工况最优。保留原始纹波 RMS 作为验收指标。

从现有 V3 分支微调的命令（准备好后由使用者启动）：

```powershell
.\run_one_stage_pushcart.ps1 train `
  --checkpoint .\logs\rsl_rl\homie_pushcart\2026-09-18_06-37-12_v3e_full\model_12600.pt `
  --quality_profile ripple `
  --level 17 --num_envs 4096 --max_iterations 1000 `
  --run_name v3_1_ripple --headless
```

当前 RSL-RL 的 `--max_iterations 1000` 表示恢复后额外执行 1000 次迭代。各消融组从同一检查点启动、使用相同额外迭代数，并更换 profile / run_name。可用 Hydra 参数覆盖，例如 `env.task.quality.high_hz=4.0`；候选权重和频段会保存到运行配置。第一轮无需重新学习 HOMIE，也没有新增机器人姿态平滑主奖励。

完整控制频率的 bench 采样：

```powershell
.\run_pushcart_bench.ps1 step `
  --policies "two_stage:logs/rsl_rl/homie_pushcart/2026-09-18_06-37-12_v3e_full/model_12600.pt" `
  --steps vx_0_to_03 wz_p03 wz_m03 hold --payloads 0 25 `
  --trace_stride 1 --out_dir logs/bench/v3_1_baseline
```

`runs.json` 新增整车质心处的合力/合力矩、各手偏航力矩贡献、参考速度、带限速度误差、带限任务载荷、倾角及轮离地遥测，并记录采样间隔与测力来源；报告保留原指标，附加车侧施力表。默认压缩 trace 的步长保持原设置，需要频谱分析时使用 `--trace_stride 1`。

鲁棒性 bench 还记录扰动发生/结束时刻，并按配置文件的恢复容差、因果滤波和持续时间统计车侧任务恢复。未恢复或被后续扰动打断的事件明确保留，恢复时间均值只计算满足恢复条件的事件，需与恢复比例一起看。`within_tolerance` 表示观察窗口开始即保持在容差内，不代表车完全没有波动。
