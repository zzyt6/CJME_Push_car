# UniFP 拔河阻抗实验：做法、训练机制与 HOMIE 双手受力的对应关系

核查日期：2026-09-28。依据：UniFP 官网视频、论文 arXiv:2505.20829v2 第 3.1–3.2、4.3–4.4 节及附录 A、C，以及官方公开 B2+Z1 代码 `unified-force/UniFP@68847a070f88d731058c3d8476929bc3b205f5bd`。本次只核查资料和新增记录，没有修改控制器或运行机器人实验。

**用户截图对应哪个实验**

截图是官网的 **Impedance Control / Tug-of-war**，对应[官方视频](https://unified-force.github.io/Compressed/Corl_PF_web4.mp4)与[论文 4.3 节](https://arxiv.org/html/2505.20829v2#S4.SS3)。视频约 10.5 s：人通过连接末端的绳索施加方向和幅度变化的拉力，四足机械臂的末端、臂姿态和机身随受力调整。论文硬件为 Unitree B2+Z1。

作者将其解释为阻抗行为：保留一个末端位置参考，允许末端在外力作用下偏移，偏离越大，恢复／抵抗作用越大。相邻的 **Force Tracking** 模式会随外力更新参考位置，卸载后留在新位置，二者不能混为一个实验。相邻的 **Base Force Tracking / Human Following** 则强调通过基座速度变化响应外力。

视频本身没有给出拉力时间序列、逐帧位置／速度命令、真机实际刚度、绳索材料和标定误差，不能从画面反推出精确实验参数。下文数值标明是论文范围还是公开训练配置。

**实验背后的控制目标**

完整阻抗关系包含弹性、阻尼、惯性项。UniFP 对慢速／准静态交互采用简化的静态关系。对于纯末端外力扰动、主动施力命令为零的阻抗模式，论文附录 A.8 给出：

```text
x_target = x_command + F_external / K
```

其中 `F_external` 是外界对机器人的力，`K` 为末端平移等效刚度，量纲 N/m。外力增大，允许位置偏移增大；在同一参考下可理解为 `F_external ≈ K × displacement`。这说明其目标并非对任何拉力都保持末端绝对不动，而是实现预设的受力—位移关系，同时保持机器人平衡。

公开 B2+Z1 配置 `gripper_force_kp_range=[200,200]`。以单轴为例，若 `K=200 N/m`，20、30、60 N 分别对应 0.10、0.15、0.30 m 的目标偏移。这只是公式与公开训练参数的换算，**不代表视频测出了这些拉力或位移，也不证明视频采用同一个 K**。该 K 不是关节 PD 的 Kp；不能把 200 N/m 直接填进关节控制增益。

位置命令也不是一个必然锁在固定世界坐标的点：论文给出相对机体的末端命令，源码将其转换到随基座 XY／航向更新、具有约定高度的参考坐标系。因此“趋向原参考”不等于“机身移动后手还要回到原世界位置”。这一点影响双臂与推车的接口设计。

对基座，作者采用另一种关系：

```text
v_base_target = v_base_command + F_base_net / D
```

这里 `D` 是将力换成速度偏移的系数，量纲 N·s/m。这是基座受力／人引导行走的目标，不能把末端的 `F/K` 位移补偿直接当成身体速度命令。论文明确指出，本工作分别处理末端与基座，将两者耦合成一个完整多接触模型仍是后续方向。

**这些行为怎样训练出来**

1. **先训练无外力的基础能力，再加入力命令和扰动。** 论文采用两阶段课程：先学全身末端到达与行走，再随机加入力命令和外力。公开配置为 `force_start_step=8000`，执行判断为 `global_steps > 8000*24`；默认每 PPO 轮 24 个环境步时约对应 8000 轮之后，而不是 8000 个物理子步。
2. **直接向刚体施力，不建立拔河人的动作模型或绳子接触模型。** 公开代码向 `gripper_idx` 对应的夹爪连杆施加三维力，调用 `apply_rigid_body_force_tensors(..., GLOBAL_SPACE)`。力命令和实际外力分别采样；仅修改网络中的力命令并不等于向机器人真的施加了力。反作用力没有通过真实物体交互单独建模，而是以等效外部净力覆盖。
3. **外力按有时间结构的曲线变化。** 论文和源码均采用渐增、保持、渐减、归零、重采样的过程，使策略经历加载、持载、卸载。它不是每个时刻完全独立抽一个随机力。
4. **训练奖励要求达到受力后允许偏移的目标。** 源码 `_reward_tracking_ee_force_world()` 计算 `x_target = x_command + (F_applied_world + F_command_world)/K`，奖励末端接近该目标；这里使用的是仿真实际施加力。力命令先由航向坐标转换到世界坐标。纯拔河阻抗对应 `F_command=0`，因此退化为上面的 A.8 关系。正负号要按“外界对机器人”和“机器人主动施力”的定义核对，不能机械复制符号。
5. **同时学习状态估计。** q、dq、机体姿态、角速度、上一动作、位置／速度／力命令和步态时钟组成观测。32 帧历史经共享编码器产生特征；估计头预测基座速度、末端位置、末端力等。公开代码还预测基座力。状态估计用仿真目标做 MSE 监督；Actor 从当前观测与编码特征输出腿和臂的关节位置目标，再由 PD 执行。

也就是说，**外力真值参与训练奖励与估计监督，但不作为部署时直接可用的传感输入**。估计和受力响应由本体历史学习得到。不能把其核心机制概括成“部署时给任意现有策略后面接一个 `JᵀF` 补偿就行”。

还有一处重要实现区别：公开 Actor 直接使用共享编码潜变量，并不只消费解码出来的力数值。估计头的训练帮助塑造编码特征，但真实动作不必经由“力标量解码 → 手写力反馈”的唯一通道。部分控制模式可以进一步把预测力转换成位置命令；官方仓库尚未公开完整真机脚本，不能声称已经核实拔河视频里每个部署分支的计算细节。

**公开训练配置中可复用的实验参数**

| 项目 | 已核查设置 | 解释 |
|---|---|---|
| 末端实际外力 | 每轴 −60 至 +60 N | 三维分量范围，不是力矢量模长最多 60 N |
| 末端主动施力命令 | 每轴 −60 至 +60 N | 与外部施力单独采样，角色不同 |
| 施力采样周期 | 3.5–9.0 s | 配置范围 |
| 渐增／渐减时长 | 各取 1–3 s 范围内的采样值 | 源码会按周期剩余时间裁剪，不能假定每次都达到 3 s |
| 中间持载时间 | 1 s | `settling_time_force_gripper_s` |
| 随机选择施力的概率 | 0.8 | 力命令／外力分别设置；不是均匀覆盖所有时刻 |
| 末端位置偏移刚度 | 200 N/m | 该公开配置为固定值，不是随机区间宽度 |
| 仿真／策略时钟 | 5 ms 物理步，4 倍降采样，50 Hz 策略 | 32 帧覆盖约 0.64 s 输入样本窗；不等于固定 0.64 s 输出延迟 |
| 训练环境数 | 4096 | 论文说明 |
| 平衡与运动约束 | 速度／末端目标跟踪、碰撞、关节／力矩限制、平滑性和步态奖励 | 不是只优化估力 MSE |

以上是公开 B2+Z1 训练路径，不是视频逐项复现实验单。尤其公开 `step()` 中 `_push_robot_base()` 的调用是注释状态，虽然配置有基座外力范围和相关奖励；不能仅凭 YAML 开关就断言这份默认脚本同时训练了基座施力路径，更不能称其完整复现 G1 演示。

**如何理解“没有力传感器”**

部署策略的主要输入是本体运动和命令历史，没有把外置六维力传感器作为必需输入。论文另外使用测力计验证力控制／估力性能；验证仪器不等于策略需要的在线输入。

拔河是定性行为演示，不是独立精度标定实验。论文第 4.1 节及附录 E 的力实验另报告约 5–10 N 的估力误差，并说明高频交互和工作空间边缘仍较困难。拔河视频证明这种策略能表现出有用的柔顺行为，不能据此推导每一瞬间都精确估计了人施加的力。

**与 HOMIE 双手末端受力的对应关系**

| UniFP 已验证／公开的内容 | 对我们的意义 |
|---|---|
| 单机械臂末端受三维力，四足腿和机械臂由统一策略协调 | 可以借鉴“手端受力—允许偏移—全身保持平衡”的训练任务 |
| 同时随机位置命令、主动施力命令和真实外力 | 可分别检验机器人主动推力与外界扰动，避免把两者训练成同一个信号 |
| 估计器与 Actor 共享本体历史编码 | 是一种候选结构；不能直接当作我们独立力头、车速头与冻结 HOMIE 的相同实现 |
| G1 实验主要针对基座力与运动响应 | 论文明确 G1 只考虑基座速度／力命令，没有证明双臂独立末端阻抗控制 |
| 单点三维力模型 | 不能直接覆盖我们双手 12 维力／力矩标签、双手内力和推车闭链 |
| 简化准静态阻抗 | 适合作为慢变外力基础实验；快速冲击、急转弯和闭链动态载荷要另测 |

公开仓库固定版本的文件树中没有 G1 专属训练／真机部署代码；README 的 sim2real 发布项仍未完成。论文 G1 演示支持方法可跨平台适配，不表示 B2+Z1 检查点直接迁移到 G1，也不表示官方已经提供 HOMIE 双手方案。

**建议我们怎样借鉴这个实验，先把问题做得可判定**

先建立与拔河对应的手端已知力试验，再逐步接回双手推车闭链。这样输入力标签可直接由施力程序确定，能分别检查估力与控制响应。下述为本项目建议，尚未实施，也不是 UniFP 原实验已经做过的双臂扩展。

- **单手加载**：左右手分别施加慢变三维力，先用较小幅度，记录静止／行走时的手位移、力估计、躯干姿态与落脚响应。固定位置模式和阻抗模式分开评分，明确目标是抗偏移还是允许柔顺偏移。
- **双手组合加载**：同向力测试总外力响应；异向力测试转矩响应；沿两掌连线的等大反向力测试不产生整体合力／合力矩的分量。两手等大反向力若不沿两掌连线，通常会产生力偶，不能统一叫“内部力”。
- **闭链推车**：再引入真实车体质量、轮地阻力和抓握约束，检验两手位移目标是否兼容。分别设计两个 `F/K` 位移可能与同一刚性车把约束冲突，需要围绕共同车把运动和内部载荷协调，不能独立平移两只手后假设闭链自动满足。

若沿用冻结 HOMIE，下层步态策略无法像 UniFP 的统一全身策略一样重新学习受力协调。我们可把这种奖励用于高层的身体速度指令与上身残差，但这是一个需要验证的层级适配，效果取决于冻结下层实际能实现的运动。

力方向尤其要对齐：当前 V5.3 双手标签是“手对车”的力，而 UniFP 纯阻抗公式中的外力是“外界对机器人”的力。对应到同一坐标系和作用点后，接触作用力方向相反。若直接拿当前标签正号代入 `x_command+F/K`，可能把顺应外力的目标写成相反方向。

建议评价三类量：真实外力与预测力的分轴误差／延迟；稳态力—位移斜率及卸载回归；平衡、速度跟踪和双手内部负荷。既不以“不倒”代替估力准确，也不以“手完全不动”评价一个本来允许位移的阻抗控制目标。
